# Техническая Документация по Кодовой Базе (SOLIS)

## 1. Ядро Системы (`Core`)

### 1.1 `Game`
Главный класс приложения, инкапсулирующий окно SFML и управляющий главным игровым циклом.
- **`Game(const std::string& title, unsigned int width, unsigned int height)`**: Инициализирует окно (`sf::RenderWindow`) и базовые параметры.
- **`run()`**: Запускает главный игровой цикл (Game Loop), обеспечивая целевой FPS (60 кадров в секунду).
- **`processEvents()`**: Обрабатывает системные события окна (например, закрытие окна).
- **`update(float deltaTime)`**: Делегирует обновление логики активному состоянию через `StateMachine`.
- **`render()`**: Очищает экран, делегирует отрисовку активному состоянию и выводит результат на экран.

### 1.2 `StateMachine`
Класс, реализующий паттерн "Конечный автомат" (State Machine) с использованием стека состояний. Позволяет переключаться между экранами (меню, хаб, бой) без жесткой связности.
- pushStatestd::unique_ptr<State> newState: Добавляет новое состояние поверх текущего (например, открытие паузы или инвентаря).
- **`popState()`**: Удаляет верхнее состояние, возвращая управление предыдущему.
- **`changeState std::unique_ptr<State> newState`**: Заменяет текущее верхнее состояние на новое (например, переход из исследования в бой).
- **`clearAndSetState std::unique_ptr<State> newState`**: Полностью очищает стек и устанавливает новое состояние (используется при поражении для возврата в Хаб).
- **`processStateChanges()`**: Отложенно применяет изменения в стеке, чтобы избежать ошибок во время итерации по активному состоянию.
- **`getActiveState()`**: Возвращает ссылку на текущее активное состояние.

### 1.3 `State`
Абстрактный базовый интерфейс для всех игровых экранов.
- **`init()`**: Вызывается при создании состояния для загрузки ресурсов и настройки UI.
- **`resume()`**: Вызывается, когда состояние снова становится активным после закрытия поверхностного состояния.
- **`handleInput()`**: Обработка ввода (клавиатура/мышь), специфичного для состояния.
- **`update(float deltaTime)`**: Логическое обновление данных (таймеры, проверки условий).
- **`render(sf::RenderWindow& window)`**: Отрисовка всех UI-компонентов и графики состояния.

### 1.4 `ResourceManager`
Синглтон (Singleton), управляющий загрузкой тяжелых ресурсов (шрифтов) для предотвращения их дублирования в памяти.
- **`loadFont(const std::string& name, const std::string& path)`**: Загружает шрифт из файла в память.
- **`getFont(const std::string& name)`**: Возвращает ссылку на загруженный шрифт, предотвращая падения программы при ошибках путей.

## 2. Игровые Сущности (`Entities`)

### 2.1 `Player`
Хранит все параметры протагониста: здоровье, жар, экипированные навыки, артефакты и статусные эффекты.
- **`takeDamage(int damage)` / `heal(int amount)`**: Изменение текущего запаса ХП.
- **`addHeat(float amount)` / `reduceHeat(float amount)`**: Управление уровнем Жара.
- **`calculateHeatGain(float baseAmount)`**: Рассчитывает итоговый получаемый Жар, применяя множители от артефактов и баффов.
- **`addArtifact(const Artifact& artifact)`**: Экипирует артефакт (пассивный бафф), немедленно применяя плоские бонусы (например, +к максимальному ХП).
- **`addStatusEffect(const StatusEffect& effect)`**: Накладывает временный эффект в бою.
- **`processTurnEffects()`**: Обновляет длительность статусных эффектов (уменьшает счетчик ходов).
- **Геттеры/Сеттеры**: Управление Эмпатией (`getEmpathy`), базовым уроном (`getBaseDamageBonus`), и порогом перегрузки (`getOverloadThreshold`).

### 2.2 `Enemy`
Представляет рядового противника в игре.
- **`takeDamage(int damage)`**: Уменьшение ХП врага с учетом модификаторов защиты.
- **`getTrait()` / `setTrait(...)`**: Устанавливает скрытую черту характера (Trait), необходимую для механики Социального боя (Договориться).
- **`getDamageModifier()` / `getDefenseModifier()`**: Модификаторы, на которые влияют механики "Манипуляции" (Take/Give).
- **`isDrainable()`**: Флаг, определяющий, можно ли использовать на враге манипуляцию вытягивания Жара.

### 2.3 `BossEnemy`
Наследуется от `Enemy`. Реализует многофазные сражения с уникальным параметром "Воля" (Willpower) вместо обычного социального поражения.
- **`addPhase(const BossPhase& phase)`**: Загрузка фаз босса (смена реплик, требуемых черт и агрессии).
- **`updatePhase()`**: Переключает фазу босса в зависимости от текущего показателя Воли.
- **`reduceWillpower()`**: Снижает Волю босса при правильном социальном ответе.
- **`getAggressionTurns()`**: Возвращает количество ходов "Агрессии" (период, когда кнопка "Договориться" заблокирована).

## 3. Менеджеры (`Managers`)

### 3.1 `DataManager`
Синглтон, отвечающий за парсинг всех баз данных игры из JSON файлов с помощью библиотеки `nlohmann/json`.
- **`loadRooms`, `loadEnemies`, `loadSkills`, `loadLore`, `loadUpgrades`, `loadArtifacts`, `loadEvents`**: Методы для чтения и десериализации JSON файлов из папки `data/`.
- **`spawnEnemy(const std::string& id)`**: Паттерн "Фабрика". Создает и возвращает уникальный экземпляр `Enemy`, заполняя его параметрами из загруженных JSON-шаблонов.
- **`spawnBoss(const std::string& id)`**: Фабрика для боссов.
- Обеспечивает доступ ко всем статичным базам через методы `getRooms()`, `getSkills()` и т.д.

### 3.2 `RunManager`
Синглтон, хранящий текущее состояние рогалик-забега (текущий уровень, счетчики, собранный лор).
- **`startNewRun()`**: Инициализирует новый забег, создает нового `Player`, применяет к нему купленные мета-улучшения из `SaveManager` и сбрасывает счетчики комнат.
- **`getNextRoomOptions()`**: Генерирует массив из 1-3 случайных комнат для следующей двери, отфильтрованных по текущему уровню.
- **`unlockLore(const std::string& id)`**: Регистрирует найденный лор, делая его доступным для `DialogueGenerator`.
- **`modifyIdeologyScore(...)`, `incrementEventProgress(...)`**: Трекинг сюжетных решений и продвижения по цепочкам квестов.
- **`incrementBloodCounter()`, `incrementMercyCounter()`**: Трекинг стиля прохождения для определения финальной концовки.

### 3.3 `SaveManager`
Синглтон для управления сохранением мета-прогрессии на диск.
- **`load()`**: Считывает `save.json`. Если файла нет, создает структуру с нулевым прогрессом.
- **`save()`**: Сериализует текущую структуру `SaveData` и записывает в `save.json`.
- **`SaveData` (struct)**: Хранит количество Искр, уровень Эмпатии, купленные улучшения, экипированные навыки и глобальные счетчики.

## 4. Механики (`Mechanics`)

### 4.1 `DialogueGenerator`
Генератор вариантов ответа для Социального боя.
- **`generateOptions(Trait enemyTrait, int currentLevel)`**: Основная логика. Анализирует открытый лор в `RunManager`. Формирует 4 кнопки диалога:
  - 1 "Верный" ответ (совпадает с чертой врага).
  - 1-2 "Нейтральных" ответа (смежные черты).
  - Оставшиеся слоты заполняет "Неверными" ответами или заглушками (если лор еще не найден).
  Возвращает перемешанный массив `DialogueOption`.

### 4.2 Основные Структуры Данных
- **`Skill`**: Описание активного навыка (название, урон, стоимость Жара, вектор эффектов `SkillEffect`).
- **`Artifact`**: Пассивный бафф (идентификатор модификатора `modifier_type` и его значение).
- **`Event`**: Сюжетное событие с вариантами выбора (`EventChoice`).
- **`StatusEffect`**: Временные эффекты боя (`type` эффекта, сила и длительность в ходах).

## 5. Игровые Состояния (`States`)

### 5.1 `MainMenuState`
Стартовый экран. Рендерит заголовок и главное меню. Обеспечивает переход в Хаб по нажатию начала игры.

### 5.2 `HubState`
Состояние "Очаг Предков" — центр мета-прогрессии между забегами.
- Реализует подменю:
  - **Shop (Магазин)**: Позволяет тратить Искры на покупку постоянных улучшений (пассивок или новых навыков), сверяясь с `SaveManager`.
  - **Inventory (Инвентарь)**: Позволяет экипировать купленные активные навыки (до 3 штук) перед забегом.
- Обновляет и сохраняет файл `save.json` после любых изменений.

### 5.3 `ExplorationState`
Состояние навигации по биому.
- Выводит описание текущей комнаты и кнопки для перехода в следующие.
- **`generateNextStep()`**: Запрашивает комнаты у `RunManager` и обновляет `ActionMenu`.
- Обрабатывает логику особых комнат:
  - Если `combat` — переключает в `CombatState`.
  - Если `lore_room` — открывает лор и добавляет в `RunManager`.
  - Если `quest` — выводит сюжетное событие и записывает выбор игрока в сохранение (изменение `ideology_score`).

### 5.4 `CombatState`
Ядро пошаговой боевки.
- Отрисовывает TopBar с ХП и Жаром, лог событий и интерфейс врага.
- Управляет деревом меню (Атака, Манипуляция, Договориться).
- **`enemyTurn()`**: Рассчитывает урон врага, применяет его к игроку.
- **`processTurnEnd()`**: Применяет механику Перегрузки (урон, если Жар > 85%) и уменьшает счетчики статусных эффектов.
- **Механика Диалога**: При выборе опции из "Договориться" анализирует флаг `isCorrect` и немедленно завершает бой победой или применяет штрафы/передает ход.

### 5.5 `EndingState`
Экран подсчета итогов игры после победы над финальным боссом.
- **`calculateEnding()`**: Анализирует счетчики убийств (`blood_counter`), пощады (`mercy_counter`) и идеологию. Используя цепочку условий, определяет, какую из Концовок выдать на экран.

## 6. Интерфейс (`UI`)

### 6.1 `UIBox`
Модульный компонент пользовательского интерфейса, на котором строится весь визуал игры без использования сложных GUI-библиотек.
- Задает прямоугольную область (`sf::RectangleShape`) с фоном, обводкой и отступами.
- **`setText(...)`**: Основной метод вывода текста.
- **`wrapText(...)`**: Внутренний алгоритм (Word Wrap), который построчно считывает символы и переносит слова на новую строку, если их ширина превышает ширину `UIBox`. Это гарантирует, что длинные описания комнат и лор никогда не вылезут за пределы экрана.
- **`setProgressBar(...)`**: Отрисовывает визуальный ползунок (прогресс-бар) внутри бокса, использующийся для индикации ХП и Жара.

## 7. Утилиты (`Utils`)

### 7.1 `GameConstants.h`
Единый конфигурационный файл для хранения "магических чисел".
- Содержит все константы баланса: стартовое ХП, порог перегрузки Жара, множители урона от перегрева, формулы манипуляции.
- Содержит пропорции UI-элементов (в процентах от размера экрана), что делает интерфейс гибким.
- Содержит константы цветов (желтый для Жара, красный для перегрузки, базовые цвета фона).
- Это позволяет геймдизайнеру легко балансировать игру из одного файла без необходимости искать цифры по всему исходному коду.
