# MVP 0 (Технический Каркас и UI)

**Цель этапа:** Поднять пустой, но полностью рабочий движок игры. Настроить окно, загрузить шрифты, реализовать архитектуру Состояний (State Machine) и создать модульную систему отрисовки интерфейса согласно TDD. Никакой игровой логики на этом этапе нет.

## 1. Задачи для ИИ-Агента (Спецификация модулей)

Агенту нужно будет последовательно реализовать следующие подсистемы:

### Задача 1. Инициализация проекта и CMake
*   **Требования:** Создать базовую структуру папок, описанную в Разделе 1 TDD (папки `src`, `include`, `assets/fonts`, `data`).
*   **Сборка:** Написать `CMakeLists.txt`, который подключает C++17, использует `FetchContent` для загрузки SFML 3.0.2 и `nlohmann/json`. Обязательно настроить пути к заголовочным файлам (`target_include_directories`).

### Задача 2. Менеджер Ресурсов (`ResourceManager`)
*   **Требования:** Реализовать паттерн Singleton (или передачу по ссылке) для класса `ResourceManager`.
*   **Функционал:** Класс должен иметь метод для загрузки шрифта (`.ttf`) из папки `assets/fonts/` в память и метод для получения ссылки на этот шрифт (`sf::Font`). 
*   **Безопасность:** Если файл шрифта не найден, агент должен предусмотреть вывод ошибки в консоль и корректное завершение программы, а не падение с *segfault*.

### Задача 3. Архитектура State Machine (Конечный автомат)
*   **Требования:** Создать базовый интерфейс `State` с чисто виртуальными методами: `Init()`, `HandleInput()`, `Update(float deltaTime)`, `Render(sf::RenderWindow& window)`.
*   **Стек состояний:** Создать класс `StateMachine`, который будет хранить состояния (например, через `std::stack` или `std::vector`) и управлять ими (методы `PushState`, `PopState`, `ChangeState`).

### Задача 4. Главный класс `Game`
*   **Требования:** Создать ядро приложения. Класс `Game` должен владеть окном `sf::RenderWindow` (разрешение по умолчанию 1280x720) и объектом `StateMachine`.
*   **Функционал:** Класс должен содержать главный цикл (Game Loop), который обрабатывает события окна (например, закрытие по крестику), высчитывает дельту времени и вызывает `Update` и `Render` у активного Состояния.

### Задача 5. Модульная система UI (`UIBox`)
*   **Требования:** Это самая сложная задача MVP 0. Агенту нужно создать класс `UIBox`, который представляет собой прямоугольную зону на экране.
*   **Параметры `UIBox`:** Должен принимать координаты, размеры (ширину и высоту), цвет фона, толщину и цвет рамки.
*   **Текст внутри `UIBox`:** Должен уметь принимать строку `std::string` и отрисовывать её с помощью `sf::Text`.
*   **Word Wrap (Перенос строк):** Агент обязан реализовать алгоритм, который рассчитывает ширину текста. Если строка не влезает в ширину `UIBox`, алгоритм должен автоматически переносить текст на новую строку.

### Задача 6. Тестовое состояние (`MainMenuState` или `TestState`)
*   **Требования:** Создать первое состояние, которое наследуется от `State`. В методе `Init()` нужно создать три объекта `UIBox`, которые строго повторяют разметку из Раздела 3.1 TDD:
    1.  **TopBar:** 10% высоты экрана. Текст: *"SOLIS: MVP 0 | HP: 100/100 | HEAT: 0%"*.
    2.  **MainDisplay:** 55% высоты экрана. Текст: Длинная тестовая строка, превышающая ширину экрана, чтобы проверить алгоритм переноса строк (Word Wrap).
    3.  **ActionMenu:** 35% высоты экрана. Текст: *"[1] Начать игру \n[2] Выход"*.
*   **Логика:** В `HandleInput()` добавить обработку нажатия клавиши `[2]` или `Escape` для закрытия игры.

# MVP 1 (Базы Данных и Навигация)

**Цель этапа:** Реализовать Data-Driven подход (чтение JSON), создать логику забега (`RunManager`) и состояние исследования (`ExplorationState`). Игрок должен иметь возможность читать описание комнаты и выбирать, в какую дверь пойти дальше.

## 1. Задачи для ИИ-Агента (Спецификация модулей)

### Задача 1. Структуры данных и `DataManager`
*   **Требования:** Создать структуры (struct) C++ для описания комнаты (на основе Раздела 16.4 TDD: `id`, `level`, `type`, `preview_text`, `description`).
*   **Парсинг JSON:** Создать класс `DataManager` (Singleton). Написать метод `LoadRooms(const std::string& filepath)`, который использует `nlohmann/json` для чтения файла `data/rooms.json` и заполняет внутренний `std::vector<Room>` (базу комнат).
*   **Безопасность:** Если файл `rooms.json` отсутствует или содержит синтаксическую ошибку, `DataManager` должен вывести понятное сообщение об ошибке в консоль и безопасно прервать выполнение (или выбросить исключение).

### Задача 2. Менеджер забега (`RunManager`)
*   **Требования:** Создать класс `RunManager`, который хранит состояние текущей сессии (забега).
*   **Функционал для MVP 1:** 
    *   Хранить переменные: `currentLevel` (начинается с 1) и `currentRoomIndex` (начинается с 0).
    *   Иметь метод `GetNextRoomOptions()`, который реализует логику из Раздела 5.2 TDD: фильтрует все комнаты из `DataManager` по `currentLevel` и случайным образом выбирает от 1 до 3 комнат в качестве следующих дверей.

### Задача 3. Состояние Исследования (`ExplorationState`)
*   **Требования:** Создать новый класс состояния, унаследованный от `State`. В главном классе `Game` изменить стартовое состояние с тестового на `ExplorationState`.
*   **Логика `Init()`:** Привязать UI-боксы к этому состоянию (сохранить разметку из MVP 0). Вызвать генерацию первой комнаты.
*   **Логика UI:**
    *   `TopBar`: Выводить текущий уровень (`"УРОВЕНЬ: " + std::to_string(RunManager::currentLevel)`).
    *   `MainDisplay`: Выводить поле `description` текущей активной комнаты.
    *   `ActionMenu`: Выводить список доступных дверей (поле `preview_text`), сгенерированных `RunManager`. Формат: `[1] Текст двери 1 \n [2] Текст двери 2...`.

### Задача 4. Обработка ввода (Навигация)
*   **Требования:** В методе `HandleInput()` класса `ExplorationState` перехватывать нажатия цифровых клавиш (`1`, `2`, `3` на клавиатуре).
*   **Условия:** 
    *   Если игрок нажал `1`, игра "входит" в первую комнату из предложенного списка.
    *   При входе `MainDisplay` очищается и в него выводится `description` выбранной комнаты.
    *   Счетчик `currentRoomIndex` увеличивается на 1.
    *   Снова вызывается метод генерации следующих дверей, и `ActionMenu` обновляется новыми вариантами.
    *   *Защита от дурака:* Если предложено только 2 двери, нажатие на `3` должно игнорироваться.

### Задача 5. Заглушка (Mock-данные)
*   **Требования:** Агент должен сгенерировать пример файла `data/rooms.json` минимум с 5-7 разными комнатами для Уровня 1 (используя типы `combat`, `lore_room`, `heat_sink`), чтобы алгоритму рандома было из чего выбирать. Не обязательно писать текст который имеет игровую ценность можешь писать в тексте чисто технический текст чтобы было более понятно.

# MVP 2 (Боевая Система и Навыки)

**Цель этапа:** Научить игру парсить врагов и навыки, создать игровые сущности (`Player`, `Enemy`) и реализовать пошаговый цикл боя в новом состоянии (`CombatState`), включая менеджмент Жара и урона от перегрузки.

## 1. Задачи для ИИ-Агента (Спецификация модулей)

### Задача 1. Игровые сущности (`Player` и `Enemy`)
*   **Требования:** Создать классы `Player` и `Enemy` согласно Разделам 4.1 и 4.2 TDD.
*   **Игрок:** Настроить базовые статы (`maxHp`, `currentHp`, `heat`). Добавить массив `activeSkills`. Добавить методы для получения урона, отхила и добавления Жара.
*   **Враг:** Настроить статы (`maxHp`, `currentHp`, `baseDamage`, `damageModifier` (по умолчанию 1.0), `defenseModifier` (по умолчанию 1.0)).

### Задача 2. Парсинг новых JSON-баз (`DataManager`)
*   **Требования:** Расширить `DataManager` для загрузки `data/enemies.json` и `data/skills.json`.
*   **Враги:** Агент должен научить систему при создании врага выбирать ему случайную черту из `possible_traits` (как описано в п. 16.2 TDD), хотя сама механика черт пока не используется — просто выводить в лог `intro_text`.
*   **Навыки:** Настроить парсинг базового урона (`base_damage`) и стоимости Жара (`heat_cost_added`).

### Задача 3. Интеграция боя в `ExplorationState`
*   **Требования:** Изменить логику входа в комнату. Если игрок выбирает дверь, которая ведет в комнату с `type == "combat"`, игра должна:
    1.  Выбрать случайного врага из массива `possible_enemies` этой комнаты.
    2.  Вызвать `Enemy::Spawn`.
    3.  Переключить State Machine в `CombatState`, передав туда сгенерированного врага.

### Задача 4. Пошаговый цикл (`CombatState`)
*   **Требования:** Создать новое состояние `CombatState`.
*   **UI Разметка в бою:**
    *   `TopBar`: Актуальные `HP` и `HEAT` игрока. Цвет текста HEAT должен становиться красным при >85%.
    *   `MainDisplay`: Разделен на 2 части (или выводит текстом): Лог боя (кто кому сколько нанес урона) и Статус Врага (имя, ХП, баффы/дебаффы).
*   **Ход Игрока (ActionMenu):** 
    *   Вывести базовое меню: `[1] Атака`, `[2] Манипуляция`, `[3] Договориться (Недоступно)`.

### Задача 5. Логика действий (Атака и Манипуляция)
*   **Требования:** Реализовать логику нажатия кнопок по формулам из Раздела 15.2 TDD.
*   **Атака:** При нажатии `[1]` ActionMenu меняется на подменю со списком экипированных скиллов игрока. Игрок выбирает скилл (например, нажимая `[1] Солнечная вспышка`) -> Наносится урон врагу, Жару игрока прибавляется `heat_cost_added`. Возврат в главное меню боя.
*   **Манипуляция:** При нажатии `[2]` открывается подменю:
    *   `[1] Поглотить:` +15% Жара игроку, `defenseModifier` врага уменьшается на 0.2.
    *   `[2] Отдать:` **Только если Жар > 0.** Жар падает (например, на 20%), ХП игрока лечится, `damageModifier` врага увеличивается на 0.2.

### Задача 6. Ход Врага, Перегрузка и Окончание боя
*   **Требования:** Как только игрок совершает действие (Атака или Манипуляция), ход автоматически передается врагу.
*   **Атака врага:** Игрок получает урон: `baseDamage * damageModifier`.
*   **Проверка Перегрузки:** В конце хода рассчитывается Жар (Раздел 15.1 TDD). Если Жар > 85%, игрок получает урон от самовозгорания.
*   **Условия выхода:**
    *   Если `Enemy.currentHp <= 0`: Вывести в лог "Победа", по нажатию клавиши вернуться в `ExplorationState` к следующим дверям.
    *   Если `Player.currentHp <= 0`: Перевести игру в заглушку `GameOverState` (или `MainMenuState`).

### Задача 7. Заглушка (Mock-данные)
*   **Требования:** Агент должен сгенерировать пример файла `data/enemies.json` и `data/skills.json` нужно добавить 2 скила, который только наносит урон и повышает жар, второй ослепляет врага из-за чего он промахивается по игроку и повышает жар игрока. Также написать 3 врага. Не обязательно писать текст который имеет игровую ценность можешь писать в тексте чисто технический текст чтобы было более понятно.

# MVP 3 (Социальная Система и Лор)

**Цель этапа:** Научить игру парсить лор, выдавать его в специальных комнатах и использовать собранные знания для генерации уникальных вариантов ответа в Социальном бою. 

## 1. Задачи для ИИ-Агента (Спецификация модулей)

### Задача 1. Парсинг Лора (`DataManager`)
*   **Требования:** Создать структуру `LoreItem` (поля `id`, `level`, `target_trait`, `pickup_text`, `dialogue_option_text`).
